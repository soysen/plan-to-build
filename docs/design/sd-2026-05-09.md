## 2. 資料 Schema 設計

### 2.1 Task 型別定義（TypeScript-style 文件，非實際程式碼）

```typescript
interface Task {
  id: string;           // crypto.randomUUID()
  title: string;        // NOT NULL, 最大 100 字
  weight: number;       // 1–5，預設 3（僅頂層任務有意義）
  deadline: string | null; // ISO 日期字串 "YYYY-MM-DD"，nullable（僅頂層任務有意義）
  done: boolean;        // 預設 false
  blobShape: string;    // CSS border-radius 八值字串，建立時隨機生成並固定
  parentId: string | null; // null = 頂層任務
  createdAt: string;    // ISO 8601
  updatedAt: string;    // ISO 8601
}
```

### 2.2 localStorage Schema

**Key**：`blob-todo-tasks`

**Value**：`Task[]` 的 JSON 字串

### 2.3 資料驗證規則

| 欄位 | 驗證規則 | 錯誤行為 |
| ---- | -------- | -------- |
| `title` | 非空字串，trim 後長度 > 0，最大 100 字 | Modal 顯示錯誤訊息，阻止送出 |
| `weight` | 整數，1 ≤ weight ≤ 5 | 滑桿限制輸入範圍，不需額外驗證 |
| `deadline` | `YYYY-MM-DD` 格式或 null | date input 的瀏覽器驗證 |
| `parentId` | 存在的 task id 或 null | 程式邏輯保證，不暴露給使用者 |

## 3. 無 API 設計（純前端）

本專案 MVP 階段無後端、無 API。所有「資料操作」皆為 localStorage 的讀寫。

### 3.1 TaskStore 介面（替代 API 的本地操作層）

```javascript
// MOD-001 TaskStore
const TaskStore = {
  // 取得所有頂層任務（parentId === null）
  getTopLevel() → Task[],

  // 取得特定父任務的子任務
  getChildren(parentId: string) → Task[],

  // 取得單一任務
  getById(id: string) → Task | undefined,

  // 取得父任務 blob 要顯示的子任務提示文字
  // 回傳最近建立且未完成的子任務 title，無則回傳 null
  getNextSubtaskHint(parentId: string) → string | null,

  // 新增任務（自動產生 id、blobShape、createdAt、updatedAt）
  add(data: { title, weight?, deadline?, parentId? }) → Task,

  // 更新任務
  update(id: string, partial: Partial<Task>) → Task,

  // 刪除任務（若為頂層任務，一併刪除所有子任務）
  delete(id: string) → void,

  // 切換完成狀態
  toggleDone(id: string) → Task,

  // 內部：從 localStorage 讀取
  _load() → Task[],

  // 內部：寫入 localStorage
  _save(tasks: Task[]) → void,
}
```

### 4.2 Blob 視覺設計規格

#### Blob 形狀生成

```javascript
// 建立任務時隨機生成，之後固定不變
function generateBlobShape() {
  const r = () => Math.floor(Math.random() * 40) + 30; // 30–70
  return `${r()}% ${100-r()}% ${r()}% ${100-r()}% / ${r()}% ${r()}% ${100-r()}% ${100-r()}%`;
}
// 輸出範例："62% 38% 46% 54% / 60% 44% 56% 40%"
```

#### Blob 大小計算

```javascript
// 重要度 1–5 → 半徑（px）
// 面積 ∝ weight，面積 = π * r²，所以 r ∝ sqrt(weight)
// BASE_RADIUS 依視窗大小和任務數量動態調整
function calcRadius(weight, baseRadius) {
  return baseRadius * Math.sqrt(weight / 3); // weight=3 時 = baseRadius
}

// baseRadius 計算（讓所有 blob 總面積約佔視窗的 60%）
function calcBaseRadius(taskCount, viewportW, viewportH) {
  const totalArea = viewportW * viewportH * 0.6;
  const avgWeight = 3; // 假設平均重要度
  const avgArea = totalArea / taskCount;
  return Math.sqrt(avgArea / Math.PI);
}
```

#### 顏色系統

```javascript
// MOD-002 ColorEngine
function getColor(deadline) {
  if (!deadline) return 'hsl(220, 10%, 40%)'; // 無 deadline → 冷灰

  const days = Math.ceil((new Date(deadline) - new Date()) / 86400000);

  if (days > 7)  return 'hsl(142, 70%, 45%)'; // 冷綠
  if (days > 3)  return 'hsl(45,  95%, 55%)'; // 黃
  if (days > 1)  return 'hsl(25,  95%, 58%)'; // 橘
  return             'hsl(0,   85%, 60%)';     // 紅（< 1 天 or 過期）
}
```

### 4.4 狀態管理策略

| 狀態類型 | 管理方式 | 說明 |
| -------- | -------- | ---- |
| 任務資料 | `TaskStore` + `localStorage` | 唯一真實來源 |
| 當前視圖（主視圖 / 子任務視圖） | JS 變數 `currentParentId` | null = 主視圖，string = 子任務視圖 |

| 編輯中的任務 ID | JS 變數 `editingTaskId` | Modal 開啟時設定 |

## 5. 部署架構

### MVP（本地檔案）

```
index.html   ←  直接在 Chrome 開啟（file:// 協議）
```

無任何伺服器、無建構步驟。

### V3（Chrome Extension）

```
manifest.json         # Extension 設定，chrome_url_overrides.newtab = "index.html"
index.html            # New Tab 頁面（原 MVP 檔案，調整 CSP）
icons/                # Extension icon（16、48、128px）
```

**CSP 調整重點**（Manifest V3 要求）：
- 移除所有 `eval()` 和 inline event handler（`onclick="..."` 改為 `addEventListener`）
- 將 `<script>` 的 `type="module"` 改為外部檔案引用
- `localStorage` → `chrome.storage.local`（API 相容，需非同步包裝）

## 6. 安全性設計

| 項目 | 處理方式 |
| ---- | -------- |
| XSS 防範 | 所有使用者輸入透過 `textContent`（非 `innerHTML`）插入 DOM |
| 資料驗證 | 每次從 localStorage 讀取時驗證結構（防止手動修改導致崩潰） |
| 無敏感資料 | 純個人任務文字，無身份驗證、無密碼、無 token |
