# 測試計畫書 (Test Plan)

## 專案名稱：康威生命遊戲 (Conway's Game of Life)

- **版本**：v1.0
- **狀態**：已確認
- **測試環境**：Vitest v1.6.0, Node.js v20.18.3, jsdom
- **測試目標**：確保遊戲引擎邏輯 (`gameEngine.ts`) 100% 符合康威生命演化規則，並包含網格初始化、互動與邊界繞回的正確性。

---

## 1. 測試範圍與指標
- **測試對象**：`src/core/gameEngine.ts` 內的所有導出函數。
- **覆蓋率指標**：核心計算函數的語句覆蓋率 (Statement Coverage) 與分支覆蓋率 (Branch Coverage) 需達 **90% 以上**。

---

## 2. 測試案例定義 (Test Cases)

### 2.1 網格初始化與狀態切換

| 案例 ID | 測試目標 | 輸入條件 | 預期輸出 | 驗證方式 |
| :--- | :--- | :--- | :--- | :--- |
| **TC-GIN-001** | 建立空白網格 | 列數 = 5, 欄數 = 5 | 產生 5x5 二維陣列，每個細胞值均為 `false` (死) | 比對陣列維度與所有元素值 |
| **TC-GIN-002** | 建立隨機網格 | 列數 = 20, 欄數 = 20, 隨機 = true, 密度 = 0.3 | 產生 20x20 陣列，存活細胞 (`true`) 數量落在 50 至 200 之間（約 30%） | 統計陣列中 `true` 的個數 |
| **TC-GIO-001** | 細胞狀態切換 (死 ➔ 活) | 3x3 空白網格，點擊 `(1, 1)` | 網格 `(1, 1)` 變為 `true`，且回傳之網格必須是**全新陣列引用 (Immutable)**，原網格維持不變 | 驗證物件引用 `newGrid !== oldGrid` |
| **TC-GIO-002** | 細胞狀態切換 (活 ➔ 死) | 網格 `(1, 1)` 為 `true`，點擊 `(1, 1)` | 網格 `(1, 1)` 變為 `false` | 比對修改後的元素值 |

### 2.2 鄰居計數與邊界繞回 (Toroidal Grid)

```text
繞回計數示意 (以 3x3 網格為例)：
[ 0, 1 ]  ➔ 設為存活
[ 1, 1 ]  ➔ 設為存活
[ 2, 2 ]  ➔ 設為存活 (此格為 toroidal 下 [ 0, 0 ] 的左上角鄰居)

當計算 [ 0, 0 ] 的鄰居時：
- 實際檢索：[2,2] (左上), [2,0] (上), [2,1] (右上), [0,2] (左), [0,1] (右), [1,2] (左下), [1,0] (下), [1,1] (右下)
- 以上活鄰居有：[0,1]、[1,1]、[2,2] ➔ 預期鄰居數 = 3
```

| 案例 ID | 測試目標 | 輸入條件 | 預期輸出 | 備註 |
| :--- | :--- | :--- | :--- | :--- |
| **TC-NGB-001** | 標準鄰居計數 | 3x3 網格，`(1, 1)` 周圍設有 3 個活細胞 | `countNeighbors(grid, 1, 1)` 回傳 `3` | 測試中心格子鄰居數 |
| **TC-NGB-002** | 邊界繞回鄰居計數 | 3x3 網格，`(0, 0)` 左上、右、右下方向設有 3 個活細胞（部分穿越邊界） | `countNeighbors(grid, 0, 0)` 回傳 `3` | 驗證 Toroidal modulo 運算 |

### 2.3 康威生命演化規則 (Conway's Rules)

我們在測試中以 `(1, 1)` 作為目標細胞，觀察其在不同存活鄰居數下的世代更迭結果：

```text
規則視覺矩陣對照表：
( 🟢 = 活細胞, ░ = 死細胞, 🎯 = 目標細胞 [1,1] )

1. 孤單死亡 (TC-RULE-001)        2. 穩定生存 (TC-RULE-002)
   ░  ░  ░                        🟢 ░  ░
   ░  🎯  ░  ➔ 🎯 死亡 (0 鄰居)   ░  🎯  ░  ➔ 🎯 存活 (2 鄰居)
   ░  ░  ░                        ░  ░  🟢
   
3. 過擠死亡 (TC-RULE-003)        4. 繁衍復活 (TC-RULE-004)
   🟢 🟢 🟢                       🟢 🟢 🟢
   ░  🎯  ░  ➔ 🎯 死亡 (4 鄰居)   ░  🎯  ░  ➔ 🎯 復活 (3 鄰居，原為死)
   🟢 ░  ░                        ░  ░  ░
```

| 案例 ID | 測試目標 | 輸入條件 (目標細胞原狀態 + 鄰居數) | 預期下一代狀態 | 規則名稱 |
| :--- | :--- | :--- | :--- | :--- |
| **TC-RUL-001** | 孤單死亡 (0 鄰居) | 🎯 活，周圍 0 個活細胞 | 💀 死亡 (`false`) | 孤單死亡 |
| **TC-RUL-002** | 孤單死亡 (1 鄰居) | 🎯 活，周圍 1 個活細胞 | 💀 死亡 (`false`) | 孤單死亡 |
| **TC-RUL-003** | 穩定生存 (2 鄰居) | 🎯 活，周圍 2 個活細胞 | 🟢 存活 (`true`) | 穩定生存 |
| **TC-RUL-004** | 穩定生存 (3 鄰居) | 🎯 活，周圍 3 個活細胞 | 🟢 存活 (`true`) | 穩定生存 |
| **TC-RUL-005** | 過擠死亡 (4 鄰居) | 🎯 活，周圍 4 個活細胞 | 💀 死亡 (`false`) | 過擠死亡 |
| **TC-RUL-006** | 繁衍復活 (3 鄰居) | 🎯 死，周圍 3 個活細胞 | 🟢 復活 (`true`) | 繁衍復活 |
| **TC-RUL-007** | 無效復活 (2 鄰居) | 🎯 死，周圍 2 個活細胞 | 💀 維持死亡 (`false`) | 無影響 |

## 3. 測試執行流程
1. **測試啟動**：在專案根目錄執行 `npm run test` (對應 `vitest run`)。
2. **斷言檢驗**：Vitest 將自動掃描 `src/**/*.test.ts` 並執行上述 10 個測試案例。
3. **報告產出**：主控台將印出各案例的 Pass/Fail 狀態。
